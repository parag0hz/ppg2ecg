# 우리 방식 한눈에 보기

작성일 2026-09-21 · 처음 읽는 사람을 위한 설명서입니다. 수치의 출처는 맨 아래 문서 목록에 있습니다.

---

## 1. 한 문단 요약

PPG(손가락·손목의 맥파)를 보고 ECG(심전도)를 만들어내는 기존 모델 **PENGUIN**은, 결과 하나를 만들 때 신경망을
**50번** 돌립니다. 우리는 신경망을 **1번만** 돌려도 되는 빠른 생성기를 준비한 다음, 그 빠른 생성기로 **같은 PPG에
대해 결과를 16개** 만들고, 그 16개를 **모아서 하나의 답**을 냅니다. 이렇게 하면 PENGUIN보다 **계산은 3분의 1만
쓰면서 심박수는 더 정확하게** 맞힙니다. 5개 데이터셋 전부에서 확인했습니다.

핵심은 **"새로운 모델"이 아니라 "결과를 뽑아 쓰는 방식"**입니다.

---

## 2. 배경: 무엇이 문제였나

### 2.1 하려는 일
```
PPG (맥파, 재기 쉬움)  ──►  [ 생성 모델 ]  ──►  ECG (심전도, 재기 번거로움)
```
스마트워치는 PPG만 잴 수 있습니다. PPG에서 ECG를 만들어낼 수 있으면 심박수, 박동 간격 같은 정보를 얻을 수 있습니다.

### 2.2 생성 모델은 "노이즈에서 출발해 조금씩 다듬는" 방식입니다
```
무작위 노이즈 ─► 다듬기 ─► 다듬기 ─► … ─► 다듬기 ─► ECG
                 (1번)     (2번)            (50번)
```
다듬을 때마다 신경망을 한 번 호출합니다. 이 호출 횟수를 **NFE**라고 부릅니다. PENGUIN은 NFE가 50입니다.

### 2.3 그냥 횟수만 줄이면 안 됩니다
PENGUIN을 1번만 돌리면 **가능한 모든 ECG의 평균** 같은 뭉개진 파형이 나옵니다. 뾰족해야 할 QRS(심전도의 큰 봉우리)가
사라집니다. 어떤 노이즈에서 출발해도 똑같이 뭉개진 결과가 나온다는 점이 나중에 중요해집니다.

---

## 3. 우리 방식: 세 단계

```
             ┌─────────────── 1단계: 1스텝 생성기 ───────────────┐
             │  신경망 1번 호출로 ECG 하나를 만드는 빠른 모델        │
             └────────────────────────────────────────────────┘
                                   │
   같은 PPG  ──►  노이즈 ①  ──►  ECG 샘플 ①  ─┐
   같은 PPG  ──►  노이즈 ②  ──►  ECG 샘플 ②  ─┤
        …                          …          ├──►  3단계: 모으기  ──►  최종 답
   같은 PPG  ──►  노이즈 ⑯  ──►  ECG 샘플 ⑯  ─┘
             └────────── 2단계: 16번 반복 (총 16 NFE) ──────────┘
```

### 1단계 — 1스텝 생성기를 준비한다
신경망을 1번만 돌려도 **뭉개지지 않은** ECG를 내는 모델입니다. 만드는 방법이 여러 가지 있고, 우리는 같은 조건에서
네 가지를 모두 시험했습니다.

| 방법 | 어떻게 만드나 | 기존 PENGUIN이 필요한가 |
|---|---|---|
| **iMF** (Improved MeanFlow) | "한 번에 끝까지 가는 법"을 처음부터 학습 | 불필요 |
| **Consistency distillation (CD)** | 학습된 PENGUIN을 선생으로 삼아 1번에 같은 결과를 내도록 학습 | 필요 |
| Reflow | PENGUIN이 만든 결과로 다시 학습해 경로를 곧게 폄 | 필요 |
| 소형 DiT | 공식 iMF 구조를 작게 줄여 처음부터 학습 | 불필요 |

**이 네 가지는 모두 남이 만든 기법입니다.** 우리가 새로 만든 것이 아닙니다.

### 2단계 — 같은 PPG로 16개를 만든다
출발하는 노이즈만 바꿔서 16번 돌립니다. 한 번에 NFE 1이므로 16개를 만들어도 **총 16 NFE**, PENGUIN 한 번(50 NFE)의
3분의 1입니다.

### 3단계 — 모은다 (이 부분이 우리 방식의 핵심입니다)

**(a) 심박수 합의 — 주 결과**
16개 각각에서 심박수를 읽은 뒤 **중앙값**을 답으로 씁니다.
```
샘플별 심박수:  72  75  71  96  74  73  70  74  76  73  48  75  72  74  73  75
                         ↑ 튀는 값                       ↑ 튀는 값
중앙값 = 73.5 bpm   ← 튀는 값에 휘둘리지 않음
```

**(b) 합의 디코딩 — 확장 결과**
심박수 숫자만이 아니라 **비트가 어디에 있는지**까지 모읍니다.
1. 16개 각각에서 R 피크(큰 봉우리) 위치를 찾는다.
2. 여러 샘플이 **같은 자리**를 가리키면 그곳을 비트 위치로 정한다(투표).
3. 각 샘플의 비트를 그 위치에 **맞춰 정렬한 뒤** 평균해 최종 파형을 만든다.
   (정렬 없이 평균하면 뭉개지지만, 정렬하고 평균하면 봉우리가 살아남습니다.)

---

## 4. 왜 작동하나

**샘플마다 조금씩 다르게 틀리기 때문입니다.**
- 1스텝 생성기는 노이즈에 따라 비트를 조금 앞에 놓기도, 뒤에 놓기도, 하나 빼먹기도 합니다.
- 이런 오차는 방향이 제각각이라, 16개를 모으면 서로 상쇄됩니다. 여론조사에서 표본을 늘리면 오차가 주는 것과 같습니다.

**반대로, 샘플이 전부 똑같으면 모아도 소용없습니다.** 이걸 실험으로 확인했습니다.

| 생성기 | 샘플 1개 | 샘플 32개 합의 | 개선 |
|---|---|---|---|
| iMF (샘플마다 다름) | 10.08 bpm | 6.45 bpm | **−3.6** |
| PENGUIN 1 NFE (뭉개져서 매번 같음) | 7.33 bpm | 7.37 bpm | 0 |

PENGUIN을 1번만 돌린 결과는 어떤 노이즈를 넣어도 같은 평균 파형이라, 32개를 모아도 나아지지 않습니다.
**"다양한 샘플 + 모으기"가 한 쌍으로 작동하는 구조**입니다.

**"그럼 PENGUIN을 16번 돌려 모으면 되지 않나?"**
됩니다. 실제로 PENGUIN 50 NFE를 4번 모으면 9.64 → 7.55로 좋아집니다. 하지만 그건 **200 NFE**입니다.
우리는 16 NFE로 6.67입니다. 같은 일을 12분의 1 비용으로 하는 셈입니다.

## 5. 무엇이 우리 기여이고 무엇이 아닌가

| 구분 | 내용 |
|---|---|
| ✅ 우리 기여 1 | **합의 추론**: 1스텝 생성기의 싼 샘플을 모아 쓰는 방식. 생성기 종류와 데이터셋에 상관없이 작동함을 보임 |
| ✅ 우리 기여 2 | **공정한 비교**: 1스텝 생성기 4종을 같은 백본·같은 학습량·같은 데이터로 비교 (이 분야에 없던 비교) |
| ✅ 우리 기여 3 | **언제 되고 언제 안 되는지**: 샘플이 다양해야 하고(4절), 비트 위치 합의는 샘플끼리 위치가 맞을 때만 된다는 조건 규명 |
| ✅ 우리 기여 4 | **평가 방식**: 환자 단위 분리, 환자별 승률, 자명한 기준선, 기존 지표의 한계 |
| ❌ 우리 것이 아님 | iMF, consistency distillation, reflow, PENGUIN 백본 — 모두 기존 기법 |
| ❌ 효과 없었음 | 백본 키우기, attention, 공식 DiT 구조, ImageNet 사전학습, KAN, 손실 함수 변형 — 6번 시도해 전부 변화 없음 |

처음 목표는 "PENGUIN에 iMF를 붙이면 좋아진다"였습니다. 실험해 보니 iMF만의 장점이 아니었고(다른 1스텝 기법도 됨),
**진짜 이득은 생성기가 아니라 "여러 개 뽑아 모으기"에서 나왔습니다.** 그래서 논문의 주인공이 바뀌었습니다.

## 6. 결과 요약

### 6.1 심박수 합의 (주 결과) — 5개 데이터셋 전부에서 PENGUIN보다 정확
| 데이터셋 | 환경 | PENGUIN 50 NFE | **우리 (16 NFE)** | 차이 |
|---|---|---|---|---|
| VitalDB | 수술실, 환자 1,156명 | 9.69 | **6.67** | **−3.01** |
| WildPPG | 웨어러블, 14명 | 13.66 | **9.27** | **−4.39** |
| BIDMC | 중환자실, 15명 | 8.93 | **6.53** | **−2.41** |
| CapnoBase | 마취, 13명 | 7.54 | **5.51** | **−2.05** |
| PPG-DaLiA | 웨어러블, 4명 | 13.42 | **12.70** | **−0.72** |

단위는 심박수 오차(bpm), 낮을수록 좋습니다. VitalDB에서는 환자의 94%, WildPPG에서는 14명 전원에서 우리가 이겼고,
VitalDB 결과는 학습을 세 번 반복해도 유지됐습니다.

### 6.2 합의 디코딩 (확장 결과) — 되는 곳과 안 되는 곳이 있음
| 데이터셋 | 비트 위치 정확도(F1): 샘플 1개 → 디코딩 | 판정 |
|---|---|---|
| VitalDB | 0.674 → **0.765** | 작동 (박동 간격 오차도 절반) |
| WildPPG | 0.371 → **0.439** | 작동 |
| BIDMC · CapnoBase | +0.01~0.02 | 미미 (원래 잘 맞아서 얻을 게 적음) |
| PPG-DaLiA | 0.147 → 0.125 | **실패** (샘플끼리 비트 위치가 제각각) |

### 6.3 속도 (창 하나, CPU)
| 모델 | 시간 |
|---|---|
| PENGUIN 50 NFE | 2,286 ms |
| 우리: 16개 합의 | 728 ms (3.1배 빠름) |
| 1스텝 생성기 1개 | 45 ms (50배 빠름) |
| 소형 DiT 1개 | 5 ms (447배 빠름) |

## 7. 한계 (논문에 그대로 쓸 내용)

1. **샘플 1개만 쓰면 우리가 지는 경우가 많습니다.** 이득은 모아야 나옵니다.
2. **파형 모양은 아직 부족합니다.** 정답 위치에 평균적인 비트 모양을 찍어 넣는 단순한 방법이 어떤 생성기보다 모양이 낫습니다.
   비트 모양 정보는 PPG에 거의 들어 있지 않기 때문입니다.
3. **합의 디코딩은 조건부입니다.** 샘플끼리 비트 위치가 맞지 않는 데이터(PPG-DaLiA)에서는 오히려 해롭습니다.
4. **디코딩한 파형은 실제 ECG보다 지나치게 깨끗합니다.** 파형 분포 지표(FD)가 나빠지므로, 파형이 아니라 비트 위치·간격 용도로 써야 합니다.
5. **심박수만 필요하다면 PPG 피크만 세어도 9.06 bpm**이 나옵니다. 샘플 1개짜리 모델과 비슷한 수준이고, 합의만 이를 확실히 앞섭니다.

## 8. 용어

| 용어 | 뜻 |
|---|---|
| PPG | 빛으로 재는 맥파. 스마트워치·산소포화도 측정기가 재는 신호 |
| ECG | 심전도. 전극으로 재는 심장의 전기 신호 |
| R 피크 / QRS | ECG에서 박동마다 나타나는 가장 크고 뾰족한 봉우리 |
| NFE | 결과 하나를 만들 때 신경망을 호출한 횟수. 계산량의 단위 |
| PENGUIN | 비교 대상인 기존 모델 (ICASSP 2026). NFE 50 |
| 1스텝 생성기 | NFE 1로 결과를 내는 생성 모델 (iMF, CD, reflow 등) |
| 합의(consensus) | 같은 입력으로 만든 여러 샘플을 모아 하나의 답을 내는 것 |
| 합의 디코딩 | 샘플들의 비트 위치를 투표로 정하고, 정렬 후 평균해 파형을 만드는 것 |
| HR 오차 | 심박수를 얼마나 틀렸는가 (bpm) |
| F1 | 비트 위치를 얼마나 맞혔는가 (±50 ms 이내면 정답, 0~1) |
| FD | 생성한 파형들의 분포가 실제 ECG 분포와 얼마나 다른가 (낮을수록 좋음) |
